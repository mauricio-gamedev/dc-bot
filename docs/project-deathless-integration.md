# Project Deathless — MiojoPlays Interactive integration plan

Status: research / blocked on official game hook

## Why this game

Project Deathless: Survival is a Unity 2D hardcore zombie survival game for Android/PC. It is a strong fit for live interaction because it already has procedural locations, survival stats, loot, weapons, vehicles, crafting and hostile encounters.

## Current compatibility finding

The official public GitHub repository currently exposes the PC distribution README/license, not the Unity project source. No public mod SDK, plugin API or documented console bridge was found during initial research.

Because of that, MiojoPlays must NOT ship an APK patch/decompilation workflow as the default integration path. The preferred path is an official lightweight integration hook from the developer.

## Minimal hook we need

The game only needs one small bridge. Preferred option:

- HTTPS polling every ~1.5–2.0 seconds
- bearer token generated by MiojoPlays pairing
- `GET /deathless/pull`
- response contains at most one whitelisted action
- unknown actions are ignored
- no remote arbitrary code execution

Example response:

```json
{
  "ok": true,
  "action": {
    "id": "random-id",
    "type": "spawn_zombie",
    "by": "viewer"
  },
  "interactionsOpen": true,
  "pollAfterMs": 1500
}
```

Alternative acceptable hook:

- local/plugin event API exposed by the game
- small Unity C# package maintained by the Project Deathless developer
- documented command/event bridge callable from a trusted companion integration

## First command set

### Help
- `!cura` — restore a controlled amount of health
- `!comida` — add a small food item
- `!agua` — add water
- `!municao` — add limited ammo
- `!loot` — spawn a random low/medium-tier loot reward

### Chaos
- `!zumbi` — spawn one zombie near but not directly on the player
- `!horda` — spawn a small zombie wave with a dedicated long cooldown
- `!infectar` — apply a controlled infection/status penalty
- `!fome` — reduce nutrition by a bounded amount
- `!sede` — reduce hydration by a bounded amount
- `!neblina` — temporary visibility/weather penalty if the game exposes it

### Rare / strong
- `!boss` — spawn a strong enemy/event only if the game has a safe spawn API
- `!airdrop` — trigger or simulate a high-value drop if supported
- `!caos` — server chooses one safe whitelisted event

## Safety rules

- no arbitrary console commands from Kick chat
- no file writes requested by viewers
- no save deletion/reset
- no permanent stat corruption
- hard caps on spawned entities and inventory grants
- per-viewer cooldown and global cooldown
- stronger actions have their own cooldown
- action queue is bounded
- game integration can be opened/closed by the owner at any time
- all actions must be reversible or naturally recoverable where possible

## Bot-side target architecture

```text
Kick chat
  -> existing Kick webhook + OAuth
  -> command parser / cooldown
  -> Deathless action allowlist
  -> secure queue on dc-bot
  -> HTTPS pull from Project Deathless hook
  -> Unity executes whitelisted event
```

The existing Mindustry pairing/session model can be reused conceptually, but Project Deathless should get a separate namespace and token prefix so neither integration can interfere with the other.

## Proposed endpoints

- `POST /deathless/pair`
- `GET /deathless/pull`

Possible future telemetry, only if the developer explicitly exposes it:

- `POST /deathless/state` for non-sensitive live state such as HP percentage, hunger, hydration, zombie count and current day

Telemetry must be optional and minimal; no device identifiers or personal data are required.

## Developer request

We should ask the Project Deathless developer for one of these, in order of preference:

1. permission + tiny Unity C# integration package/hook;
2. official mod/plugin/event API documentation if one exists privately;
3. collaboration on a safe MiojoPlays Interactive bridge;
4. confirmation that no supported integration path is currently available.

We do not need the full game source to integrate safely if the developer can expose a small, stable, allowlisted event bridge.
